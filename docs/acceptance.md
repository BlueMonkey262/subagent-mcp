# Implementation acceptance plan

This is the release checklist for the multi-backend subagent MCP server. It is deliberately evidence-oriented: an independent reviewer must be able to mark every row **PASS**, **FAIL**, or **SKIP** from a test report and attached fixtures. A row passes only when its stated evidence and assertions exist; implementation presence alone is not evidence.

## Test environment and evidence rules

Required baseline:

| Dependency | Accepted version | Preflight evidence | Skip rule |
|---|---:|---|---|
| Node.js | `>=22` | `node --version` captured in test report | Never skipped for unit/fake-adapter tests. |
| Claude Code | `2.1.261` | resolved executable, `claude --version`, and `system/init.claude_code_version` | Local integration suite may report `SKIP: claude missing/version mismatch/auth fixture unavailable`; a release candidate may not claim Claude support while skipped. |
| Claude Agent SDK types | `0.3.220` | installed package version captured when protocol conformance fixtures are regenerated | May skip type-regeneration locally, not the checked-in fixture conformance test. |
| Codex CLI | `0.153.3` | `codex --version` and schemas from `codex app-server generate-json-schema --experimental` / `generate-ts --experimental` | Local live tests may skip if no writable isolated Codex state or credentials; release support requires an actual app-server transcript, not schema-only evidence. |
| OpenCode | `1.17.6` | resolved executable and `opencode --version` | Local live tests may skip if loopback binding/provider auth is unavailable; OpenCode remains “experimental/unsupported” until all promotion probes in P4-09 pass. |
| Cursor Agent CLI | `2026.10.16-e3cb207` | resolved `agent` executable and `agent --version` | Deterministic fixture coverage ships with the adapter; local live tests may skip if the CLI is not authenticated. A release candidate may not claim Cursor support while skipped. |

Every integration test must use a temporary project and isolated backend state, scrub secrets from artifacts, impose a hard wall-clock deadline, reap child processes, and leave the source tree unchanged except for explicitly asserted fixture output. Mock-model endpoints must bind loopback only. A test that needs a real provider request must be opt-in and clearly report cost/auth prerequisites.

Checked-in evidence consists of: unit/JavaScript test output; fake-adapter integration output; redacted golden stdin/stdout/SSE/HTTP transcripts from the exact pinned CLI; process invocation assertions; and filesystem snapshots for storage/config behavior. Unknown/additive protocol fields must be tolerated and retained in bounded diagnostics; missing required discriminators or correlation IDs must fail explicitly.

## Phase 2 — approval state machine and Claude approval bridge

| ID | Requirement | Test case and exact pass evidence |
|---|---|---|
| P2-01 | Static deny/allow rules run before heuristics; deny wins conflicts; unmatched follows configured `allow`, `deny`, or `escalate`. | **Unit table:** tool and Bash-pattern matches, path normalization, conflicting rules, case/argument boundaries, unmatched defaults. | P2-02 | Heuristic policy cheaply allows ordinary writes inside canonical cwd and always escalates `sudo`, `rm -rf`, force-push, network egress, writes outside cwd, `.git`, `.claude`, and credential paths. | **Adversarial unit corpus:** relative paths, `..`, symlinks, quoted/compound shell commands, mixed case, shell wrappers, URL/download tools, credential filename variants. | P2-03 | A parked request returns `needs_approval` with sufficient, safely rendered evidence. | **Fake integration:** approval event makes blocking `spawn_agent` return request ID, agent/backend, tool and structured input/command, canonical cwd, affected paths/diff summary, untrusted reason, and expiry; no transcript required. | P2-04 | `resolve_approval(request_id, decision)` supports `allow`, `deny`, `allow_for_session`, blocks until the next externally visible state, and is idempotent. | **State-machine unit/integration:** each decision advances pending→resolving→resolved and returns next `completed`, `needs_approval`, or `running`; duplicate same decision returns stored result without second wire reply; contradictory/unknown/expired/cancelled request rejects; resolve/completion/interrupt races yield one terminal result. |
| P2-05 | Session allow is native for Codex and synthetic for Claude/OpenCode; it never becomes project/user persistence. | **Adapter translation unit:** Codex current reply is `acceptForSession`; legacy is `approved_for_session`; Claude produces only session-destination `updatedPermissions` or bridge synthetic rule; OpenCode sends one-shot allow plus synthetic rule if native “always” is absent. | P2-06 | Every parked approval has a bridge watchdog and fails closed independently of backend timeout. | **Fake-clock unit:** expiry denies or interrupts exactly once, marks stable expired state, releases waiter, records timeout, ignores late backend/parent resolution, and bounds pending-map growth. ## Cross-phase release scenarios

These scenarios are mandatory after their constituent phases pass:

1. **Happy path per backend:** list roster → foreground spawn with explicit model → intermediate normalized events hidden from final result → completed text/usage/ID → resume context-dependent follow-up → record outcome.
2. **Approval loop per backend:** spawn provokes harmless unmatched command → `needs_approval` evidence → `allow_for_session` → next state blocks to completion or a second distinct approval → identical later command does not re-escalate → another session does.
3. **Safety path:** hostile child output plus untrusted approval reason never creates an unsanitized parent-facing control-looking string and never affects policy.
4. **Background path:** background spawn returns immediately; events are retrieved from cursor during SSE/NDJSON gaps; stop and completion race; exactly one terminal event/result and no process/timer leak.
5. **Capacity path:** mixed backends at 20 active agents, rate/backend failures, one parked approval, nested depth; the 21st/depth-3 spawn is rejected, existing agents remain controllable, slots recover on terminal states.
6. **Restart/failure path:** restart MCP server with completed routing data and backend session metadata; behavior is explicit for resumable versus backend-lost sessions, raw records survive, synthetic session approvals do not leak, and model is never inferred.

## Unresolved risks and acceptance disposition

| Risk | Required disposition before release |
|---|---|
| Claude's permission flag is hidden and stream protocol may drift. | Pin `2.1.261`, feature-detect init capabilities, run P2-CL-01/P2-CL-02 in CI or release qualification, and fail closed if forced ask is not observable. Named-MCP permission endpoint remains out of scope unless separately proven. |
| Codex app-server framing/runtime behavior and approval delivery were not live-verified in the protocol note; approvals may stall. | P3-08 is a hard gate for claiming Codex support. Keep codec thin, strict timeout/watchdog, redacted golden transcript, and explicit experimental warning until it passes. |
| OpenCode routes, auth scheme, event envelopes, terminal predicate, pending-permission query, and persistence are unverified; SSE has regressed. | Keep backend unsupported/experimental until P4-09. Never ship brief-derived routes without a golden probe. Polling and watchdog are mandatory; absence of queryable pending permission must become bounded timeout, not a hang. |
| A backend/provider may exhaust rate limits before the global 20-agent cap. | Surface normalized retry/rate-limit errors, preserve supervision, bound retries, and exercise capacity scenario with injected throttling. Do not silently lower/raise the contractual cap. |
| Same cwd and permissions means concurrent children can conflict. | No false isolation claims. Record cwd, serialize only same-session operations, surface file/backend conflicts, and document that cross-agent filesystem coordination remains the parent/orchestrator's responsibility. |
| Output scanning can miss obfuscated injection or alter legitimate prose. | Maintain adversarial corpus, scan all parent-facing paths at final assembly boundaries, keep scanner idempotent, and record sanitized-vs-raw diagnostics without exposing raw hostile text to parent context. |
| Routing feedback is biased, sparse, non-stationary, and may expose prompts/paths. | Separate observed/judged data, version keys, recency, exploration flag, samples/confounders; gitignore project raw records; bound/sanitize injected digest; provide scope deletion/retention policy before broad deployment. |
| Orchestrator norm can drift or over-delegate; routing Claude through MCP loses native panel/tasks/background/cache benefits. | Keep native Agent initially, preserve direct tools, measure hook/delegation route ratios, and make any future routing change a separately reviewed data-backed decision. |

## Final sign-off

A release is accepted only when all rows for every advertised backend are PASS, non-advertised optional backend rows are explicit SKIP with the reason above, `npm run check`, `npm test`, and `npm run build` pass, the cross-phase scenarios pass, and no production process/port/timer remains after the suite. The sign-off artifact records commit, OS, dependency versions, skipped rows, fixture hashes, and reviewer initials. “Implemented but not probed” is FAIL for any claim that depends on an installed CLI.
